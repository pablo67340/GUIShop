GUIShop Modded Edition

Proper shop screens for NeoForge, built on over a decade of GUIShop

Minecraft ${modded.mc.version} on NeoForge ${neoforge.version} or newer

Overview

GUIShop has been a Bukkit shop plugin since 2012, through fourteen years of Minecraft versions and the thousands of servers that have run it. This is the NeoForge edition, and it is not a port in name only. A plugin can only draw inside a chest inventory, so every shop ever built with GUIShop was a grid of 54 slots with filler panes around the edges and arrows glued to the bottom row. A mod has the whole screen. So that is what this uses.

Shops are real screens. They reflow to the size of your window, they search, they sort, they scroll, and they show the same item tooltips the rest of the game does. Nothing is laid out on a fixed grid, nothing needs a filler pane, and nothing needs a page arrow in slot 48.

Everything a server owner does is done in game. Add a shop, add an item, set its price, pick its material, edit the messages, change the settings. No file editing, no restarts, no reloading.

Install

This mod is required on the client and the server. The screens are drawn client side and every price and permission decision is made server side, so both halves have to be present. Single player works with no extra setup.

Features

Shops that behave like screens

  • Resizes to the window instead of a fixed 54 slot grid
  • Search box, sorting, and a filter that hides what you cannot afford
  • Full vanilla item tooltips, including enchantments, potion effects and attribute modifiers
  • Configured names, lore and colours are respected, and dark text is lifted so it stays readable on the dark chrome

Buying and selling

  • Click any item for a quantity selector with buy and sell
  • /sell opens a container to tip items into. Close it and everything the shops buy is sold, paid for in one go, with whatever they will not buy handed straight back
  • Where several shops buy the same item at different prices, the best price for the player wins
  • Prices are never read from the client. Every amount is calculated on the server from the config

Editing, without the shift clicking

  • Press Edit, then click an item. That is the whole interaction
  • The editor shows a large preview that updates as you change the item, next to every property it has
  • Values come from pickers built off the live registries, so items, blocks, mobs, enchantments and sounds from other mods are all offered and none of them can be mistyped
  • Sounds have a play button so you can hear one before choosing it
  • Fields the chosen item type ignores are drawn as inert, so a shortcut does not ask you for a sell price
  • Add and delete shops and items from the interface. Clicking a newly added shop creates it and puts you inside it, ready to fill

Settings in game

  • A tabbed settings screen: client preferences for every player, server settings for anyone permitted
  • Titles, price lore formats, currency formatting, messages, disabled worlds, trade sounds and more
  • Changes are applied and written by the server, never by the client

Item metadata, all of it

Everything the plugin ever supported on an item is applied here too:

  • Custom names and lore with colour codes
  • Enchantments at any level
  • Potions, splash potions, lingering potions and tipped arrows
  • Fireworks, with multiple explosions, colours, fades, flicker and trail
  • Player heads by UUID or by Base64 skin texture
  • Mob spawners with any entity type
  • Custom model data, item flags and raw NBT

Economy

There is no Vault here, so the mod keeps its own per player balances. Buying charges, selling pays, and the amounts are stored on the server.

Commands

/shop          Open the shop menu
/shop <name>   Open a shop directly
/sell          Open the sell container

Permissions

Server settings and the editor are available to anyone holding guishop.edit, to operators, and to the owner of a single player world. The node is registered with the NeoForge permission API, so LuckPerms and anything else that implements it will see it.

Permission is checked again on the server for every single change. Nothing is trusted because the client offered it.

Configuration

Config lives in <game>/guishop/ as JSON: one file per shop in shops/, plus menu.json, settings.json and messages.json.

Coming from the Bukkit plugin? Drop your existing shops/ and menu.yml in and they are converted to JSON automatically on first start. Every original is kept as a .yml.bak beside it, so nothing is destroyed and you can always look at what you had.

Slot numbers in an old config are read and then ignored. There is no grid to place things on any more, so ordering is simply the order of the entries in the file.

A shop file

{
  "title": "&a&lBlocks",
  "items": [
    {
      "id": "STONE",
      "type": "ITEM",
      "buy-price": 10,
      "sell-price": 5,
      "shop-name": "&7Stone",
      "lore": ["&fA basic building block"]
    },
    {
      "id": "DIAMOND_SWORD",
      "type": "ITEM",
      "buy-price": 500,
      "enchantments": "SHARPNESS:5 UNBREAKING:3"
    }
  ]
}

You will rarely need to look at this. Everything in it can be set from the editor.

Not in this build yet

This is an alpha, and it is worth being plain about what is missing. These all exist in the Bukkit plugin and are still to be brought across:

  • Worth display, which writes sell values into item lore
  • Statistics tracking and the placeholder surfaces built on it
  • Economy commands: /bal, /pay, and the admin give, take and set commands
  • Bundled default configs, so a fresh install currently wants configs from an existing GUIShop setup to start from

Everything else works. If you hit something that does not, the Discord and the GitHub issues are both read.

The Bukkit plugin

Still maintained, still separate, and unaffected by any of this. If you run Paper, Spigot, Folia or Bukkit, you want GUIShop rather than this.

Both editions now sit on one shared core, so pricing, the config model and the shop logic are a single implementation rather than two that drift apart.
